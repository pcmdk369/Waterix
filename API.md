# WATERIX — API Reference

All routes are same-origin and return JSON for API errors where possible. The API currently has no authentication layer; do not expose it as a public multi-tenant service without adding authorization and abuse controls.

## Health

### `GET /api/health`

Returns service health metadata.

```json
{ "status": "ok", "service": "WATERIX™ AI Watermark Removal Engine", "timestamp": "2026-01-01T00:00:00.000Z" }
```

## Upload

### `POST /api/upload`

Content type: `multipart/form-data`; required field: `file`.

Current server-side upload limit: 35 MiB. The frontend currently applies a slightly different client-side limit; align these limits before release.

Successful response includes:
- `jobId`
- `mediaType` (`image` or `video`)
- `filename`
- `originalUrl`
- `width`, `height`, and optional `duration`

## Apply watermark

### `POST /api/watermark/text`

JSON body:
- `jobId` — required.
- `text` — optional text (defaults to WATERIX).
- `options` — watermark configuration object. Common fields include `fontFamily`, `fontSize`, `isBold`, `isItalic`, `color`, `opacity`, `rotation`, `position`, `customX`, `customY`, `margin`, `repeat`, `startTime`, `endTime`, `movement`, `background`, and `backgroundColor`.

### `POST /api/watermark/image` or `POST /api/watermark/logo`

JSON body:
- `jobId` — required.
- `logoDataUrl` — required base64 image data URL.
- `options` — scale, opacity, rotation, position, custom coordinates, margin, repeat and video timing/movement options.

### `POST /api/watermark/video`

JSON body:
- `jobId` — required.
- `text` or `logoDataUrl` — choose the text or logo path.
- `options` — shared watermark configuration.

These endpoints return a processing acknowledgement; poll the job endpoint for completion.

## Restore selected region

### `POST /api/image/remove` (alias: `/api/remove/image`)

JSON body:
- `jobId` — required.
- `maskDataUrl` — mask generated by the image editor.
- `bbox` — optional selection bounds where applicable.

### `POST /api/video/remove` (alias: `/api/remove/video`)

JSON body:
- `jobId` — required.
- `bbox` — required object: `{ "x": 0, "y": 0, "width": 100, "height": 100 }` in source-video pixels.

Both endpoints acknowledge asynchronous processing. Video cleanup uses FFmpeg delogo in the current implementation.

## Job status

### `GET /api/job/:job_id`

Returns job identifier, media type, status, stage, progress, original URL, processed/download URLs when complete, and an optional error.

Possible states in the server job model: `queued`, `processing`, `completed`, `failed`.

## Media and download

- `GET /api/media/:job_id/original` — stream original media.
- `GET /api/media/:job_id/processed` — stream processed output when available.
- `GET /api/download/:job_id` — download processed output when available.
- `DELETE /api/job/:job_id` — delete job state and its temporary directory.

Video media streaming supports HTTP byte ranges. Range validation should be strengthened before public deployment.

## Error behavior

Typical status codes:
- `400` — missing/invalid request data, unsupported upload or upload limit.
- `404` — unknown/expired job or output not ready.
- `500` — unexpected processing/server error.

Do not rely on error message strings as stable machine-readable codes; a versioned error schema is a future improvement.
